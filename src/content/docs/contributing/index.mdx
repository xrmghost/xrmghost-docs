# Contributing

This section explains how to contribute to the XrmGhost public documentation (`xrmghost-docs`).

If you want to report a product bug, request a feature, or start an open conversation, use [Community](/community/) instead.

## Guides

| Guide | Description |
|---|---|
| [How to Add a New Docs Page](/contributing/public-docs-workflow/) | Frontmatter rules, folder naming conventions, and how to find the product owner for your change |

## Quick Rules

- Every `.mdx` file **must** have `title` and `description` frontmatter.
- Edit only the files owned by your team — see [Content Ownership](/architecture/content-ownership/).
- Placeholders are allowed and preferred over fake content — mark them with `> **TODO**:`.
- Do not edit generated content by hand — it will be overwritten by the pipeline.

Read [How to Add a New Docs Page](/contributing/public-docs-workflow/) — it covers the full workflow end to end.
