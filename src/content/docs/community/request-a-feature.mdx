# Request a Feature

Use this path when you want XrmGhost to support a new capability or improve an existing one.

Open feature requests in the public repository: [Create a feature request](https://github.com/xrmghost/xrmghost/issues/new/choose)

## Before You Request

- Search existing issues and discussions for similar proposals.
- Frame the request around the problem you need to solve, not only the implementation you prefer.
- Keep the scope focused so maintainers can evaluate it quickly.

## What to Include

- The problem and why it matters
- The current workaround (if any) and its limits
- The desired outcome
- Real usage context (team workflow, CI constraints, plugin lifecycle, and so on)
- Optional proposal for API, CLI UX, or behavior

## How Requests Are Evaluated

Maintainers review feature requests based on user impact, alignment with product direction, implementation complexity, and overlap with existing roadmap items.

## What Happens Next

A maintainer may ask follow-up questions, link related work, and move the request into planning when it is ready.
