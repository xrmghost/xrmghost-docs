# Getting Started with the CLI

The `xrmghost` CLI (invoked as `xg`) is the primary way to run Dataverse plugins, manage environments, and interact with the XrmGhost ecosystem from a terminal.

This guide covers installing the CLI, then orienting yourself — how to explore available commands, confirm your setup, and find your way into the main workflows.

## Install the CLI

The primary channel is the **signed ZIP for Windows x64**, published on the release page of the public repository, [github.com/xrmghost/xrmghost/releases](https://github.com/xrmghost/xrmghost/releases). Install the asset named `xrmghost-cli-<version>-full.zip`: it carries `xg.exe` and, in the `bin\` folder next to it, the signed host that executes your plugins — there is no separate host download.

> **TODO:** The first signed stable ZIP of the CLI is not published yet. The direct download link for the stable asset will be added once it is on the release page, as part of ADO-2619.

1. **Verify the signature before installing.** The publisher to expect and how to check it, including WDAC policies, are in [Trust and WDAC](/cli/trust-and-wdac/).
2. **Extract the ZIP** to a folder of its own, for example `C:\Tools\XrmGhost`, keeping `xg.exe` and `bin\` together.
3. **Add the folder that contains `xg.exe`** — not its `bin\` subfolder — to your user `PATH`, then open a new shell.

**Coming from the .NET global tool?** The old installation left an `xg` shim in `%USERPROFILE%\.dotnet\tools`. Run `Get-Command xg -All` (or `where xg` from `cmd`): if a line points to `.dotnet\tools`, remove it with `dotnet tool uninstall -g XrmGhost.Cli`, or put the ZIP folder before it in `PATH`. The first line must be the `xg.exe` you extracted, so that only one `xg` answers.

The .NET global tool is soft-deprecated: the `XrmGhost.Cli` package stays on NuGet, but it is no longer the recommended channel. `winget install XrmGhost.Cli` is not available yet — it follows the first signed stable ZIP and the external review of `winget-pkgs`; see [winget publication](/cli/winget-publication/). Alpha builds are not signed and may be blocked by Smart App Control.

The full walkthrough, with prerequisites, is in [Getting Started](/getting-started/#1-install-the-cli).

## Confirm the CLI is available

Once the binary is in place, verify it responds:

```bash
xg --version
```

You should see a version header showing the CLI version and the bundled Core version. If the command is not found, make sure the folder that contains `xg.exe` is on your `PATH` and that you opened a new shell after changing it.

## Discover available commands

The fastest way to understand what the CLI can do is to ask it:

```bash
xg --help
```

This prints the top-level command tree. For any command or subcommand, you can append `--help` to drill deeper:

```bash
xg env --help
xg license --help
xg run --help
```

The `--help` surface is always up to date with the installed version, so it is the most reliable reference while you orient yourself.

## Main command areas

The CLI organises its functionality into the following top-level areas:

| Command | Purpose |
|---|---|
| `run` | Execute a Dataverse plugin using a scenario file |
| `generate-scenario` | Create a template JSON scenario file for a plugin |
| `env` | Add, list, switch between, and manage environment configurations |
| `license` | Activate a license, check status, and retrieve your machine ID |
| `doctor` | Run health checks to diagnose configuration or connectivity issues |
| `privacy` | Display information about data collected by the tool |

These areas are stable entry points. Each has its own `--help` page.

## A safe first exploration path

If you are new to the CLI, the following sequence lets you explore without making any changes:

1. **Check your license status** — understand what tier and features are available to you:
   ```bash
   xg license status
   ```

2. **List configured environments** — see what Dataverse environments (if any) are already set up:
   ```bash
   xg env list
   ```

3. **Run diagnostics** — confirm connectivity and configuration are healthy:
   ```bash
   xg doctor
   ```
   Use `--verbose` for detailed diagnostic output:
   ```bash
   xg doctor --verbose
   ```

None of the commands above modify state. They are read-only discovery steps.

## When you are ready to act

Once you are oriented, typical next actions are:

- **Add an environment** — use `xg env add` to start the interactive wizard for connecting a Dataverse environment.
- **Generate a scenario file** — use `xg generate-scenario` to create a JSON template for the plugin you want to test.
- **Run a plugin** — once a scenario file is prepared and an environment is active, use `xg run` to execute the plugin out-of-process.
