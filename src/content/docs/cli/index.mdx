# XrmGhost CLI

The XrmGhost CLI (`xg`) is the primary developer interface for the XrmGhost ecosystem. It is distributed as a signed ZIP, `xrmghost-cli-<version>-full.zip`, on [GitHub Releases](https://github.com/xrmghost/xrmghost/releases/latest), and gives you terminal access to the main workflows: executing Dataverse plugins out-of-process, managing environment configurations, handling licensing, and diagnosing problems.

## Who the CLI Is For

The CLI is aimed at developers who:

- write and test Dataverse plugins locally before deploying to a Power Platform environment
- need scriptable, repeatable runs as part of a CI workflow
- prefer an AI-agent-first workflow or a terminal-first experience over a GUI

## What the CLI Does

| Command group | Purpose |
|---|---|
| `init` | Prepare the machine to run plugins — the first command after extracting the ZIP. Checks the prerequisites, resolves or repairs the Framework Host, and names the next step |
| `run` | Execute a Dataverse plugin using a scenario file, with the Framework Host running in the background |
| `generate-scenario` | Create a template scenario JSON for a given plugin, ready to pass to `run` |
| `env` | Add, edit, delete, list, activate, and switch Dataverse environment configurations |
| `license` | Activate your license, view its status and tier, and retrieve your machine's platform ID |
| `doctor` | Run environment and configuration health checks to diagnose connectivity or setup issues; read-only unless `--fix` |
| `privacy` | Display information about telemetry data collection and local storage |
| `setup host` | Advanced: install or update the Framework Host in the managed install root |

`run` uses the Framework Host bundled in the `bin\` folder next to `xg.exe` first, then the managed install root, then legacy locations; when none is found, it points to `xg init`. Because the bundled host takes precedence, `setup host` and `doctor --fix` do not change the host of a ZIP install: update it by extracting a newer ZIP.

For the full flag-level detail of every command and sub-command, see the [CLI Reference](/cli/reference/) section.
