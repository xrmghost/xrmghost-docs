# `xg privacy`

## Synopsis

```shell
xg privacy
```

## Description

`xg privacy` prints a structured summary of every category of data that XrmGhost collects, stores, or transmits. The command exits immediately after printing; it does not open a browser or make network requests.

The output covers five distinct areas:

### 1. Platform ID

When the XrmGhost CLI is first run, it generates a unique GUID called the **Platform ID** (internally `StoredMachineGuid`). This identifier is:

- stored locally in your user application data directory
- printed to the console by this command alongside the current value
- transmitted to XrmGhost servers for **licensing validation** and **anonymised usage analytics**

The Platform ID persists across CLI updates. It is the primary key used to associate your machine with an activated license.

### 2. Local Hardware Context

On each startup the CLI computes a **hardware contextual salt** from:

- the primary network adapter's MAC address
- the operating system description
- the processor count
- the current username

This value is hashed locally and used to harden activated license files against being copied to a different machine. **The salt itself is never transmitted to XrmGhost servers.**

### 3. Other Information Sent Remotely

For licensing, analytics, and error reporting the following additional data may be sent alongside the Platform ID:

| Field | Example source |
|---|---|
| IP address | Inferred at connection time |
| Machine name | `Environment.MachineName` |
| OS description | `RuntimeInformation.OSDescription` |
| .NET runtime description | `RuntimeInformation.FrameworkDescription` |
| XrmGhost CLI version | Embedded assembly version |
| Username | `Environment.UserName` |
| User domain name | `Environment.UserDomainName` |

### 4. Usage Analytics and Error Reporting

XrmGhost may collect anonymised information about commands run, features used, and errors encountered. All telemetry is linked to your Platform ID. The purpose is to identify popular workflows, prioritise improvements, and diagnose bugs.

Each telemetry record also carries a **release channel** field, `channel`, emitted as `prod` or `dev` to identify the release channel of the CLI build that produced it:

- **`prod`** — a **stable** version of the XrmGhost CLI: a released, non-prerelease version.
- **`dev`** — a **prerelease** version (for example one with an `-alpha` suffix), or a local build without a recognisable version.

The value depends only on the XrmGhost CLI version, not on how the CLI was installed (winget, NuGet or ZIP). `channel` is a build/release constant, **not personal data**, and it is subject to the same opt-out as the rest of this section.

### 5. Opting Out of Telemetry

Set the environment variable `XRMGHOST_TELEMETRY=0` before running `xg` to stop the transmission of CLI telemetry:

```shell
# Linux / macOS
export XRMGHOST_TELEMETRY=0

# Windows (PowerShell)
$env:XRMGHOST_TELEMETRY = "0"
```

With the opt-out set, the usage analytics, error reporting, traces and metrics described in section 4 are not collected, queued or uploaded.

- **Only the exact value `0` disables telemetry** (surrounding whitespace is ignored). Any other value (for example `false`, `no` or `off`), or leaving the variable unset, keeps telemetry enabled.
- **Telemetry already queued stays on disk.** Data queued on this machine before you opted out is neither uploaded nor deleted while `XRMGHOST_TELEMETRY` is `0`; it is left on disk unchanged.

The opt-out covers telemetry only. It does **not** disable:

- **license validation** — license and API-key validation keep contacting XrmGhost servers;
- **machine registration** — your Platform ID and the device details listed in section 3 are still sent to XrmGhost servers to register the machine;
- **local hardware context handling** — the hardware contextual salt described in section 2 is still computed locally on each startup to protect your activated license.

For the full privacy policy visit: **https://www.xrmghost.tech/legal/privacy-policy**

## First-run privacy notice

The first time you run a **stable** version of the XrmGhost CLI interactively, it prints a short privacy notice **once**, before any telemetry is sent and before the machine is registered with XrmGhost servers. The notice points to `xg privacy` and to the online privacy policy.

A run shows the notice only when **both** of these are true:

- **The CLI version is stable** — a released, non-prerelease version. Prerelease builds (versions with an `-alpha` suffix) never show the notice.
- **The output is not redirected** — the CLI is writing to an interactive terminal. When output is redirected to a file or piped to another command (for example in a CI pipeline), the notice is not shown.

When the notice is shown, the CLI records that fact by writing a file named `first-run.sentinel`. Redirected or piped runs and prerelease runs **neither show the notice nor write the sentinel**, so the notice still appears on your first interactive run of a stable version, even if the CLI has already run many times in CI or as a prerelease.

The sentinel lives in the same directory as the Platform ID file `machine_id.dat` (see the storage path table in [`xg license get-platform-id`](/cli/reference/license-get-platform-id/)):

| Platform | Sentinel path |
|---|---|
| Windows | `%LOCALAPPDATA%\XrmGhost\XrmGhostCli\first-run.sentinel` |
| Linux | `$XDG_DATA_HOME/xrmghost/xrmghostcli/first-run.sentinel` (falls back to `~/.local/share/xrmghost/xrmghostcli/first-run.sentinel`) |
| macOS | `~/Library/Application Support/xrmghost/xrmghostcli/first-run.sentinel` |

To see the notice again, delete `first-run.sentinel`: the notice is shown again on the next interactive run of a stable version. Delete only that file — deleting `machine_id.dat` from the same directory generates a new Platform ID and invalidates licenses bound to the old one.

## Documentation site analytics

`docs.xrmghost.tech` uses Pirsch Analytics for website analytics. Pirsch is cookieless: it does not set cookies on your device, does not process personal data, and does not use persistent identifiers to recognize or track you across visits or websites. It provides only aggregated statistics about website visits, such as page views, referrers, and general browser or device categories, so this site does not display a cookie banner for analytics. Pirsch website analytics are separate from the CLI telemetry described above. For details see the [Privacy Policy](https://www.xrmghost.tech/legal/privacy-policy).

## Options

This command has no flags or options.

xg privacy
